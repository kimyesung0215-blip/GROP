# GROP 볼트 결정 기록

볼트 자체의 구조와 운영에 대한 결정. 프로젝트별 결정은 `projects/<slug>/decisions.md`에 둔다.
추가만 하고 기존 항목은 고치지 않는다.

---

## D001 · 2026-10-09 · 새 볼트 GROP으로 시작, ys_lab 미승계
- 결정: 기존 ys_lab을 잇지 않고 새 볼트 `GROP`(Great Repository Of my Project)을 만든다.
- 근거: ys_lab은 원격에 README 첫 커밋 하나뿐이라 보존할 내용이 없음.
- 주체: 사용자

## D002 · 2026-10-09 · 원본은 git 속 마크다운, 편집기는 옵시디언
- 결정: 원본 저장소는 GitHub의 마크다운, 편집은 옵시디언, 포트폴리오는 볼트에서 생성한다. Notion은 원본으로 쓰지 않는다.
- 근거: 어떤 도구·AI에서도 읽히는 형식 유지. 원본이 둘이 되면 현재 문제가 재발.
- 기각한 대안: Notion(독자 포맷, 내보내기 손실), Obsidian+Notion 병행(원본 이중화)
- 주체: Claude 제안, 사용자 채택

## D003 · 2026-10-09 · 프로젝트별 폴더 구조 (8월 "루트 단일 파일" 결정 변경)
- 결정: `projects/<slug>/`에 README.md와 decisions.md 두 파일로 시작. 다른 파일은 필요할 때 추가.
- 근거: 범위가 결정 기록에서 전체 활동 + 포트폴리오로 넓어져, 프로젝트 단위 개요가 필요.
- 주체: Claude 제안, 사용자 채택

## D004 · 2026-10-09 · 공개/비공개를 저장소 둘로 분리, 볼트는 하나
- 결정: 볼트 안 `private/`를 별도 비공개 저장소로 두고 공개 저장소의 .gitignore로 제외한다.
- 근거: GitHub 공개 설정과 접근 권한은 저장소 단위라 폴더별 설정 불가.
- 주체: Claude 제안, 사용자 채택

## D005 · 2026-10-09 · 공개↔비공개 양방향 링크 허용
- 결정: 링크 방향 제한 없음. 대신 `private/` 파일명을 중립적으로 짓는다.
- 근거: 공개 쪽에 노출되는 건 파일명뿐이라 위험은 이름에 있음. 연결 차단은 손해가 더 큼.
- 기각한 대안: 비공개→공개 단방향만 허용
- 주체: 사용자

## D006 · 2026-10-09 · 동시 편집은 잠금 대신 소유권 분리로 해결
- 결정: 에이전트는 자기 브랜치에만 쓰고, 원장은 추가만 하며, main 반영은 사용자가 승인한다.
- 근거: 잠금 파일은 중단·경쟁 상태 처리 비용이 원래 작업보다 큼.
- 주체: Claude 제안, 사용자 채택

## D007 · 2026-10-09 · 개인 기록용 볼트 USOM 분리
- 결정: 개인 기록은 별도 볼트 `USOM`(Unconscious Side of Mind)에 둔다. 지금은 생성만 하고 방향성만 남긴다.
- 주체: 사용자

## D008 · 2026-10-09 · GitHub 공개 저장소 GROP 생성 및 연결
- 결정: GitHub에 공개 저장소 GROP을 만들고 로컬 GROP 폴더를 연결하여 push한다.
- 주체: 사용자
- 출처: 현재 대화의 공개 저장소 생성·연결·push 요청
- 공개 제외: 기존 규칙의 private/와 개인 작업 상태를 제외한다. 에이전트가 플러그인 설치 파일 및 로컬 설정(.obsidian/plugins/)도 공개 제외 규칙에 추가한다.
