# GROP 볼트 결정 기록

볼트 자체의 구조와 운영에 대한 결정. 프로젝트별 결정은 `projects/<slug>/decisions.md`에 둔다.
추가만 하고 기존 항목은 고치지 않는다.

## D001 · 2026-10-09 · 새 볼트 GROP으로 시작, ys_lab 미승계
- 결정: 기존 ys_lab을 잇지 않고 새 볼트 `GROP`(Great Repository Of my Project)을 만든다.
- 근거: ys_lab은 원격에 README 첫 커밋 하나뿐이라 보존할 내용이 없음.
- 주체: 사용자

## D002 · 2026-10-09 · 원본은 git 속 마크다운, 편집기는 옵시디언
- 결정: 원본 저장소는 GitHub의 마크다운, 편집은 옵시디언, 포트폴리오는 볼트에서 생성한다. Notion은 원본으로 쓰지 않는다.
- 근거: 어떤 도구·AI에서도 읽히는 형식 유지. 원본이 둘이 되면 현재 문제가 재발.
- 기각한 대안: Notion(독자 포맷, 내보내기 손실), Obsidian+Notion 병행(원본 이중화)
- 주체: Claude 제안, 사용자 채택

## D003 · 2026-10-09 · 프로젝트별 폴더 구조 (8월 "루트 단일 파일" 결정 변경)

- 근거: 범위가 결정 기록에서 전체 활동 + 포트폴리오로 넓어져, 프로젝트 단위 개요가 필요.

## D009 · 2026-10-10 · Obsidian 기록·복구 설정과 수동 공개 적용
- 결정: 새 링크는 일반 Markdown 상대 경로로 생성하고, 내부 링크 자동 업데이트를 켠다. 새 노트는 현재 파일과 같은 폴더, 새 첨부파일은 현재 폴더 아래 assets/에 저장한다. assets/는 실제 첨부 시 생성하며 빈 폴더는 미리 만들지 않는다.

### [다층구조] 프로젝트 폴더는 README(지도) → 주제 노트 → 결정 상세의 여러 층으로 나눈다
한 파일 원장만으로는 AI가 토큰 검색으로 맥락이 잘린 줄만 가져오거나 파일 전체를 읽어야 했고, 항목 형식에 맞추느라 과정·수치·시행착오가 깎였다. 사용자는 "여러 파일을 타고타고 들어가서 깊은 내용을 읽는" 구조를 원했다. `decisions.md`는 모든 결정의 짧은 원장이자 토큰 색인으로 남기고 항목마다 `상세:` 링크를 단다. 주제 노트는 단계 폴더(예: `33차/`, `34차/`, `파생/`), 중요한 결정은 `결정/`에 둔다. 기준은 `docs/NOTE_SPEC.md`. 버린 대안: 한 파일 원장(맥락 손실), 결정 하나당 파일 하나(흐름이 안 보임), 주제 노트만(중요 결정의 경위가 흩어짐). 음향 부양에 먼저 적용하고 로봇손은 검증 후 옮긴다.

### [수정기준] 원자료는 고치지 않고, 원장·노트는 사실 오류를 직접 고친다
첫 커밋 이후 원장을 추가만 하는 규칙은 git이 이미 보존하는 역사를 파일 안에서 한 번 더 쌓아, 오타·링크 정정마다 항목이 늘어 데이터가 과도해질 위험이 있었다. 판정 질문 "이 기록이 그 시점에 일어난 일을 맞게 적었나?"로 나눈다. 틀리게 적었으면(사실 오류·표현·출처·링크) 직접 고치고, 판단이 바뀌었거나 철회했으면 새 항목 + `관련:`, 당시엔 맞았고 나중에 더 알게 된 사실이면 당시 기록을 두고 새 항목을 만든다. 주체·채택·검증·수치·출처를 고치면 이유를 적은 수동 커밋으로 남긴다(Obsidian 자동 백업은 이유가 남지 않음). `private/raw/`는 원장이 출처로 가리키는 근거라 수정하지 않는다. 버린 대안: 첫 커밋 이후 추가만 하는 기존 규칙(정정 항목 누적).

### [결정층제외] 결정만 모은 상세 파일 층(결정/)은 만들지 않는다
[다층구조]에서 정한 `결정/` 층은 주제 노트의 진행 흐름이 결정 경위까지 담게 되면서 내용이 겹쳤다. 같은 결정의 주체·채택이 두 파일에 적히면 어긋날 수 있어, 기준은 `decisions.md` 하나로 두고 노트는 `관련 결정: [토큰]`으로 원장을 가리킨다. 위층(README·상위 노트)은 하위 노트에 무슨 내용이 있는지만 적고 요약하지 않는다(세부 수정이 하위 노트 하나로 끝나게). 노트 하나는 질문 하나이며 하위 질문은 별도 노트로 뗀다. 템플릿은 사용자 작성안을 바탕으로 `docs/NOTE_SPEC.md`에 둔다.
주체: AI 제안 (위층은 목록만 두기는 본인 제안)
채택: 확인필요 (결정/ 층 제외에 대한 명시적 답 없음)
