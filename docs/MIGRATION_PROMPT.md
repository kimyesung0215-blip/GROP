# MIGRATION_PROMPT — 프로젝트 이관 프롬프트 (1단계: 사실 이관)

기존 Claude 프로젝트(또는 다른 에이전트)의 기록을 GROP으로 옮길 때 쓰는 프롬프트.
규칙은 여기 쓰지 않는다. 규칙은 `AGENTS.md`와 `docs/ENTRY_SPEC.md`에 있고, 이 프롬프트는 그 파일을 가리키기만 한다.

이관은 두 단계다 (`docs/decisions.md`의 `[기록2단계]`).
- **1단계 (이 프롬프트)**: 원문에 있는 사실·결정을 옮긴다. 사고 과정은 재구성하지 않고, 2단계에서 다룰 후보만 표시한다.
- **2단계**: 전 프로젝트 이관이 끝난 뒤, 후보 항목에 대해 AI가 질문하고 본인이 답하는 인터뷰로 사고 과정·교훈을 채운다.

## 사용법

1. 옮길 프로젝트의 Claude 프로젝트(또는 그 기록이 있는 에이전트) 안에서 새 세션을 연다. 프로젝트 안의 대화는 밖에서 검색되지 않으므로 반드시 그 안에서 연다.
2. 아래 프롬프트의 `< >` 네 군데만 채워서 붙여넣는다. 과외·컨택처럼 개인 정보가 섞인 프로젝트는 대상을 `private/<slug>/`로 쓴다.
3. 볼트 폴더 접근 권한을 허용한다.
4. 보고를 받으면 `확인필요` 목록을 훑고, 변경 내용(diff)을 검토한 뒤 push한다. 끝나면 아래 이관 기록 표에 한 줄 추가한다.

## 프롬프트

```
[<프로젝트명>] GROP 이관 (1단계: 사실 이관)
볼트: C:\Users\HOME\Documents\GROP
대상: <projects 또는 private>/<slug>/
루트 README.md, AGENTS.md, docs/ENTRY_SPEC.md를 읽고 그 규칙에 따라 이관해.

이 프로젝트의 원본 결정 기록과 접근 가능한 대화를 확인하고, 아직 원장에 없는 결정만 추가해. 특히 <이 프로젝트에서 꼭 찾을 결정>을 찾아줘.
원문에 남아 있는 시행착오(예상과 결과가 달랐던 일, 철회·기각한 판단)는 빠짐없이 결정 항목으로 옮겨. 다만 원문에 없는 이유나 사고 과정은 추측해서 채우지 마. 그건 나중에 내가 직접 채울 거야.
방향 전환, 판단 오류, 핵심 설계에 해당하는 항목은 프로젝트 README.md 끝에 "## 2단계 회고 후보" 목록으로 탐색토큰과 한 줄 사유만 적어 둬.

프로젝트 README.md도 원문과 대조해 역할·기간·현재 상태·결과물을 갱신해. 접근하지 못한 원자료는 명시해.
파일을 쓴 뒤에는 실제로 저장된 내용을 다시 읽어 확인해.
마지막에 추가·정정 항목, 확인필요 항목, 2단계 회고 후보, README 변경, 커밋 결과를 짧게 보고해.
```
