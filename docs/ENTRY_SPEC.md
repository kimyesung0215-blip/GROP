# 결정 기록 기준

프로젝트와 볼트의 결정 원장에 새로 기록하는 항목의 단일 기준이다. 일상 기록과 이관에 같은 최소 형식을 쓴다. 진행 로그·학습 설명·산출물 본문에는 이 형식을 강제하지 않는다. 기존 커밋된 항목은 일괄 변환하지 않는다.

## 필수 5줄

```text
### [탐색토큰] 한 줄 결론
근거와 버린 대안 (원문에 없으면 "원문에 기록 없음")
주체: 본인 / AI 제안 / 팀 / 확인필요
채택: 제안 / 채택 / 보류 / 철회 / 확인필요
출처: 대화 제목·날짜 또는 원본 항목
```

- 각 줄은 독립된 정보다. 근거·대안이 여러 개면 둘째 줄을 필요한 만큼 설명할 수 있다. 근거와 버린 대안 중 없는 부분만 `원문에 기록 없음`으로 표시하고, 그럴듯한 이유를 보충하지 않는다.
- `주체`는 해당 판단·제안의 주체, `채택`은 그 제안의 처리 상태다. AI 제안을 사용자가 명시적으로 수용했다면 `주체: AI 제안`, `채택: 채택`이다. 수용 여부를 확인할 수 없으면 `채택: 확인필요`로 쓴다. `본인`은 볼트 소유자를 뜻한다.
- 출처는 다시 찾을 수 있게 쓴다. 원본 항목은 파일 경로와 탐색토큰을 적는다. 대화 날짜를 모르면 지어내지 말고 날짜 미상으로 표시한다. 원문 없이 요약본만 남았다면 출처에 요약본임을 명시하고, 요약만으로 판단 주체·채택 여부를 확정하지 않는다.
- 탐색토큰은 해당 원장 안에서 중복되지 않게 한다. 정의되지 않은 약어·용어는 항목 안에서 풀어 쓴다. 다른 항목을 열지 않아도 결론을 이해할 수 있어야 한다.

## 선택 항목

해당될 때만 추가하며, 빈 칸을 만들지 않는다.

- `검증: 실측 / 계산 / 문헌·사양 / 검증대기` — 숫자·정량 판정이 있을 때 근거에 맞게 적는다. 혼합된 경우 대상 수치별로 구분한다. 이 표기는 근거 종류와 확인 상태를 나타내며, 계산·문헌·사양이라는 이유만으로 실제 성능이 검증된 것은 아니다. 출처로 구분하지 못하면 검증대기로 둔다.
- `날짜:` — 결정이 이루어진 날짜를 원문으로 확인할 때만 쓴다. 이관 날짜와 혼동하지 않는다.
- `관련 항목:` — 정정·승계·연결에 필요할 때 파일 경로와 탐색토큰을 적는다. 커밋된 항목의 정정에는 이전 항목을 반드시 가리킨다.

## 기존 기록 호환

2026-10-10 로봇손 이관분 47건은 구 어휘와 형식을 보존한다. 해석 참고: `이론값 ≈ 계산`(문헌·추정이 섞였으면 원문 확인), `폐기 ≈ 철회`(설계안의 포기인지 판단의 번복인지 문맥 확인), `검증됨`은 실측·계산·문헌 중 무엇인지 별도 확인. 대응표만으로 주체·채택·검증을 확정하거나 기존 내용을 재작성하지 않는다.

## 기록 시점과 보존

첫 커밋 전의 이관 초안은 원문 대조로 직접 수정할 수 있다. 커밋된 항목은 추가 방식으로 정정한다. 첫 커밋은 보존 기준점이며, 사실 검증이나 사용자 채택의 증거는 아니다. 세션 종료·최신 파일 재확인·비공개 경계는 루트 `AGENTS.md`를 따른다.
