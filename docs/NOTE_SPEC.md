# NOTE_SPEC — 프로젝트 노트 기준

`projects/<slug>/` 안의 README와 주제 노트가 따르는 기준. 결정 원장 항목 형식은 `ENTRY_SPEC.md`.

## 1. 구조

```
projects/<slug>/
├── README.md           ← 지도. 개요·역할·기간·상태, 그리고 노트 목록(각 노트에 무슨 내용이 있는지)
├── decisions.md        ← 모든 결정의 짧은 원장 = 탐색토큰 색인. 항목마다 `상세:` 링크
└── <단계>/<주제>.md     ← 주제 노트. 질문 하나를 끝까지
    └── (하위 질문은 같은 폴더의 별도 노트로 떼고 링크로 잇는다)
```

- **노트 하나 = 질문 하나.** 진행 흐름에서 다른 질문이 갈라지면 하위 노트로 뗀다.
- **위층은 목록만.** README와 상위 노트는 "이 노트에는 이런 내용이 있다"만 적고 하위 내용을 요약하지 않는다. 세부를 고치면 그 노트 하나만 고친다.
- **결정의 주체·채택·검증 기준은 `decisions.md` 하나.** 노트는 경위를 쓰고, 각 단계에 `관련 결정: [토큰]`으로 원장을 가리킨다. 결정만 따로 모은 상세 파일은 만들지 않는다.
- **읽는 순서:** README 노트 목록 → 해당 노트의 "지금 알 수 있는 답" → 필요하면 진행 흐름·하위 노트. 토큰을 알면 `decisions.md`에서 찾아 `상세:` 링크로 바로 간다.

## 2. 칸의 세 종류

| 종류 | 칸 | 비었을 때 |
|---|---|---|
| 필수 | 지금 알 수 있는 답 / 범위와 원자료 대조 / 진행 흐름 각 단계의 계기·실제로 한 일·관찰·결과·근거 / 아직 비어 있는 부분 | 비울 수 없다 |
| 기록 없음 표기 | 당시 내 생각 / 그때의 해석과 고민 / 예상과 달랐던 점 | "원문에 기록 없음"이라고 쓴다. 인터뷰할 곳을 알려 주는 정보라 지우지 않는다 |
| 해당 시 | 나머지 전부 | 칸째 뺀다. "없음"으로 채우지 않는다 |

- "현재 판단에 이른 경로" 표는 판단이 세 번 이상 바뀐 주제에서만 쓴다.
- 목적은 그 주제의 모든 내용을 담는 것이다. 원자료에 있는 것은 빠짐없이 옮기되, 없는 것은 지어 쓰지 않는다.

## 4. 기록 원칙

- 원문에 있는 것만 쓴다. 자세히 쓰는 것과 지어내는 것은 다르다.
- 발언은 따옴표로 인용하고 누가 했는지 적는다(본인 / AI / 팀원 / 외부).
- AI의 해석·추정은 그렇다고 표시한다. 수치는 실측·계산·사양·설정값 중 무엇인지 적는다.
- 비공개 경계는 `AGENTS.md`를 따른다. 팀원은 "팀원", 외부 연락 상대는 "외부 전문가"로 쓰고 실명·연락 원문은 `private/projects/<slug>/`에만 둔다.
- 노트·원장의 수정 기준은 `AGENTS.md` 쓰기 1번을 따른다.

## 5. 링크

- 마크다운 상대 링크, 파일 단위. 원자료 안의 위치는 절 이름을 글로 적는다(제목 앵커는 Obsidian과 GitHub에서 형식이 달라 깨지기 쉽다).
- 폴더로 링크하지 않는다. Obsidian은 폴더 링크를 열지 못하고 같은 이름의 빈 노트를 만든다. 폴더 대신 그 폴더의 `README.md`로 건다.
- 아직 없는 노트로 가는 링크는 허용한다(쓸 예정인 노트). README 노트 목록에 "작성 전"으로 표시한다.
- 노트를 새로 쓰면 이미 있는 관련 노트의 "연결되는 질문"과 원장 항목의 `상세:`도 함께 이어 양방향으로 만든다.
- 비공개 파일 링크는 Obsidian에서만 열리고 GitHub에서는 깨진다(허용).
- 첨부(이미지)는 노트 폴더의 `assets/`. 영상은 저장소에 넣지 않고 외부 링크로.
