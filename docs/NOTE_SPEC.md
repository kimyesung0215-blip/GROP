# NOTE_SPEC — 주제 노트·결정 상세 기준

`projects/<slug>/` 안의 README·주제 노트·결정 상세가 따르는 기준. 원장 항목 형식은 `ENTRY_SPEC.md`.

## 1. 층

```
README.md            ← 지도. 무엇이 어느 노트에 있는지
decisions.md         ← 모든 결정의 짧은 원장 = 탐색토큰 색인. 항목마다 `상세:` 링크
<단계>/<주제>.md     ← 주제 노트. 흐름·과정·수치를 자세히
결정/<토큰>.md       ← 중요한 결정만. 경위를 끝까지
```

읽는 순서: README 지도 → 필요한 주제 노트 하나 → 필요하면 결정 상세. 토큰을 알면 `decisions.md`에서 토큰을 찾아 `상세:` 링크로 바로 간다. 질문 하나에 프로젝트 전체를 읽지 않는다.

## 2. 주제 노트

frontmatter: `project`, `stage`(예: 33차), `period`, `sources`(원자료 경로).

섹션 (해당 없으면 뺀다):
- **요약** — 3~5줄. 이 노트만 보고 질문에 답할 수 있는지 판단하는 용도
- **배경** — 왜 이 문제가 생겼나
- **과정** — 시간순. 날짜 소제목. 시도·실패·정정·수치·누가 무엇을 했는지
- **현재 상태** — 확정된 값·구성
- **시행착오와 정정** — 틀렸던 판단, 누가 잡았나
- **열린 문제** — 미해결·확인필요
- **관련 결정** — 원장 토큰과 결정 상세 링크
- **원자료** — `private/raw/` 경로

## 3. 결정 상세

맨 위에 `ENTRY_SPEC` 5줄(+선택 줄)을 원장과 같게 둔다. 그 아래 `## 경위`, `## 버린 대안`, `## 수치·근거`, `## 이후 영향`. 원장 항목과 결정 상세가 다르면 원장이 기준이고, 다른 점은 정정 항목으로 처리한다.

## 4. 기록 원칙

- 원문에 있는 것만 쓴다. 자세히 쓰는 것과 지어내는 것은 다르다.
- 발언은 따옴표로 인용하고 누가 했는지 적는다(본인 / AI / 팀원 / 외부).
- AI의 해석·추정은 `(AI 해석)`으로 표시한다. 수치는 실측·계산·사양 중 무엇인지 적는다.
- 비공개 경계는 `AGENTS.md`를 따른다. 팀원은 "팀원", 외부 연락 상대는 "외부 전문가"로 쓰고 실명·연락 원문은 `private/projects/<slug>/`에만.

## 5. 링크

- 마크다운 상대 링크, 파일 단위: `[독립클럭탈락](../결정/독립클럭탈락.md)`. Obsidian·GitHub 양쪽에서 동작한다.
- 링크 글자는 탐색토큰 그대로 쓴다. 검색은 토큰 글자로, 탐색은 링크로 한다.
- 비공개 파일 링크는 Obsidian에서만 열리고 GitHub에서는 깨진다(허용).
- 첨부(이미지)는 노트 폴더의 `assets/`. 영상은 저장소에 넣지 않고 외부 링크로.
